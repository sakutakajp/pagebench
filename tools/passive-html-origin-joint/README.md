This is an unpublished passive-only successor to Slot29. It performs the existing one-use admitted Node HTTPS GET, never executes JavaScript and never opens a browser. The production document transport, headers, TLS, DNS, response limits and admission predicates are unchanged. No origin/path permission is added.

The old source-form and position marginals cannot identify which position belongs to the absolute HTTPS reference, or whether its origin is approved. Two closed tests construct identical old projections with different actual origin membership or different position/form pairings. The Slot29 stored projection cannot answer either question retrospectively.

The added channel classifies explicit absolute HTTPS script src attributes only, after HTML entity decoding. Node WHATWG URL and the actual existing ORIGINS/originMask implement the origin tuple check; pathname decoding matches the existing pre-origin URL validity check. STAGING_HTTPS and IMAGE_HTTPS mean tuple membership, not permission for that resource path. The separate guard_on_attribute checks membership, parsed userinfo and fragment, just as the existing origin predicate. Port is default-or-absent versus nondefault. Empty @/# markers are distinguished from nonempty values without storing their values. Browser request normalization is not observed. Unclean syntax is UNKNOWN; relative and protocol-relative references remain unresolved even with base. No claim is made that this reference is the historical refused Chrome request or that a parser-inserted script proves a delivery-layer modification.

Position is lexical, never browser DOM or rendering. Any whole-document lexical ambiguity coarsens all new positions to UNKNOWN_OR_AMBIGUOUS; this is expected to remain possible on the next real document. The existing base classification remains available, but no resolution is attempted.

The inherited parser still scans the same body once with its old budgets and old counters. A subclass observes the same script callbacks independently of the old hint/src caps. It sends at most 256 decoded eligible attributes / 32 KiB through a private anonymous fd3 pipe in RAM to the Node parent. This is not stdout/stderr, a file, a log, an artifact or a network channel. The complete document was already held in parent RAM. URI strings are used transiently to project constants; the pipe Buffer is overwritten on exit, without claiming secure erasure of runtime strings. No URI, hostname, path, query, fragment value, credential value, header, source text or hash of any of these appears in public output or is persisted. Parser stdout contains the inherited fixed counters plus protocol metadata only. Public metadata never includes private byte lengths. Invalid/duplicate/gapped private protocol fails the entire parse closed.

The original two-second parser deadline and 64 KiB subprocess buffer remain; bounded private32KiB plus fixed stdout stays inside this envelope. Public rows are limited to64 fixed-enum combinations, counts saturate at1024. Input/row limits, unretained counts, unclassifiable attributes and saturation are explicit. observed_absolute_https is observations retained for classification, not all document sources; incomplete/ambiguous coverage never proves absence. Relative/hints cannot consume the new absolute-only input budget. Existing 256 KiB body and8KiB final Link bounds remain.

The new workflow uses depth2, exact new branch/title/parent/attempt1, two exact Node versions, immutable source hashes, actual unit receipts, exact single push-run API metadata and exclusive attempt marker before the sole document GET. API/event models in local tests are fabricated; actual source/hash/filesystem and loopback TLS tests are real. No live call or GitHub mutation is performed during preparation. This route does not measure Lighthouse or save a score/report/D1.
