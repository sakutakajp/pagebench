## What the extra output proves

supervisor/child with the same prerequisite and 45-second child deadline.
It returns the original producer result unchanged, including all failures and
unsafe-continuation stops. It reads fixed parent fields only between child
lifetimes. Original `topCaseVerdict` computes case status, continuation,
initial-original predicate, uncaught predicate and hook predicate. Only fixed
first/end sample classes, child-started, reason/cleanup/phase and bounded Chrome
version are added to the diagnostic journal; no page data, text count or raw
parent/top proof is retained there. Chrome is labelled as the original parent
final field, later original producer field, never as a new independent version
probe. Unknown version or missing result stays unknown.

The fixed journal writes at INITIAL, each case BEGIN/RETURN and producer return
or failure: normal maximum 14 synchronous bounded writes, hard maximum16, each
32KiB. It has only six constant case rows. These writes may affect diagnostic
timing and are not claimed performance-equivalent. No CDP or browser operation
is added. A writer failure marks a prefix gap or leaves a missing journal; it
does not change the original gate result. Pending/never-returned is UNKNOWN;
only original producer not_run can produce NOT_RUN_CONFIRMED.

The always publisher reconstructs two independent fixed views:

* the existing startup receipt, checked by exact schema/SHA/run with Node error
  class/phase/cleanup only, via `public-top-diagnostic/project.mjs`;
* the bounded original top-predicate journal, checked for fixed cases/enums,
  identity, budget, source labels and state combinations.

It emits agreement of fixed fields or MISMATCH/UNKNOWN. Neither a passed receipt
nor passed diagnostics authorizes live. The actual original top/240/400/startup/
counter proofs, process monitors, binary identity and full JIT remain required.
Missing diagnostics are not invented as successful gates or absence of errors.
The combined public output explicitly says it is CLOSED fixture metadata, not
current-page evidence, pixel proof, an authenticated exception or Nuxt causality.

The asynchronous first sample is AFTER matched FCP, not FCP itself. Controlled
tests distinguish already-ERROR_500 first sample, missing hook, uncaught
predicate failure, missing/unstarted result, uncertain cleanup, Node producer
fault and proof persistence failure. None identifies Slot18's historical failed
case; its actual case and Chrome remain unknown. No mock500 timer was changed.
